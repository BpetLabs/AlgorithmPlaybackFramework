## Why This Project

While extensively studying LeetCode and similar coding problems for interviews, I realized how time consuming it was becoming. I saw an opportunity to create a debugging-like experience, with blocks moving across the screen and a slider to step through the algorithm in real time across any language.

I built this to help me study, but also to explore AI-assisted coding and learn how to create a website using React. That is why the framework uses React, with animations powered by Framer Motion. I also chose this project because I love to help others succeed and have the opportunities for success I have had.

I am not a frontend developer. I have spent my career working behind the scenes on cloud services, tooling, and infrastructure to support cloud scale. Building a frontend website is new territory for me.

AI allowed me to create something that would have taken me several months to learn and code on my own, if I finished it at all. But there is a downside to using AI to learn: it is also a crutch. While I learned how to create, design, and manage a website, and built what I consider a unique framework, I still cannot write React code without the use of AI in any form. In that respect, I have not learned React, and that is OK. Looking back, React may have been unnecessary. An HTML-based animation framework might have made more sense for this project. The rapid pace of AI progress since I started this project in my spare time early in 2026 has been astounding.  Who knows how good it will be when you are reading this.

Once the framework is in place, you can use the provided AI skills and template to create animations in minutes, then tweak each problem to get the result you want.  I was able to do this with the cheapest consumer AI models. AI has opened up so many possibilities. I plan to continue to work on a new large project every year and push the boundaries of what is possible.

I have been using this to build a website with interactive animations of my favorite coding questions. That would have been impossibly time consuming without AI and the skills that I have developed through this project. Yes, using AI is still coding, and it still takes considerable effort and knowledge to build something novel, useful, and maintainable.

Do I like coding interview problems and find them valuable, especially in an AI-driven coding world? Not really, particularly given how insanely time consuming studying for them can be. For those who have been out of the interviewing loop for a long time, preparing can easily take a hundred hours or more, and you can still face a question you struggle to solve within the time limit. I have been there myself, and I hope my website can help streamline that process so that you have knowledge available to work through it.

Even in a world where you may never write code by hand again, I understand why coding problems are used: they provides a common baseline for evaluating candidates across programming languages, with objectively verifiable results. Interviews should, and do, focus on many other things as well. But even before AI, these problems were mostly irrelevant to my day-to-day work. In my two decades of professional experience, I have only needed to write solutions remotely resembling these puzzles a handful of times.
